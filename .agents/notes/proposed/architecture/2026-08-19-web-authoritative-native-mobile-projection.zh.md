# Agent Note: Web 权威的原生手机映射

Status: proposed

[English](2026-08-19-web-authoritative-native-mobile-projection.md) | 中文

## Problem

原生手机端目前只公开了 Web 对话产品的一部分能力，而桌面应用已经呈现了被接受的 Web 体验。

当前缺口包括会话生命周期操作、工作区操作、图片附件、队列操作、消息级恢复和完整交互表单。

为了管理手机产品行为而增加不相关的桌面页面，会形成第二个产品面，也无法缩小 Web 与手机端的功能差距。

## Proposal

Web 客户端继续作为可见对话行为、状态转换和用户术语的权威产品规范。

桌面应用保持不变，继续承载现有 Web 体验和本地 DSH 运行时。

原生手机端通过适合 iOS 和 Android 的原生组件，渲染相同的持久会话历史、投影、工具视图、交互状态和设置值。

移动网关仅对既有 DSH 会话、工作区、交互、附件和设置操作公开经过认证的薄路由；它不引入第二个智能体循环、会话存储或桌面专属产品行为。

## Mapping order

首先实现对话一致性：完整历史分页、工具卡片视图、图片附件、队列操作、取消、与重试相关的错误状态和交互响应。

其次实现会话和工作区生命周期：由现有 DSH API 已提供的创建、重命名、分叉、归档、恢复、成员关系和工作区排序操作。

仅当某项 Web 行为已经能通过既有 DSH 操作获得，且能安全地在手机上表示时，才继续实现设置和低频辅助界面。

## Alternatives considered

**独立的桌面手机管理产品面** 被拒绝，因为桌面端已经具备被接受的 Web 产品，而设备管理并不能缩小对话一致性缺口。

**WebView 手机客户端** 被拒绝，因为产品需要原生手机导航、安全区、手势和平台输入行为，同时仍保留 Web 产品语义。

**独立手机智能体或复制的会话存储** 被拒绝，因为这会将持久历史、工具执行、审批和模型上下文拆分到不同客户端。

## Acceptance criteria

本次工作不修改桌面应用源码和可见 Web 体验。

每个手机端对话控件都映射到一个既有 DSH 操作，并观察与 Web 相同的持久会话事件。

手机端支持适合在手机上使用的 Web 对话生命周期，UI 特有差异仅限于原生交互惯例。

针对网关、手机逻辑、类型和模拟器的回归检查证明：消息、工具结果、审批和会话生命周期操作在桌面 Web 视图与原生手机端之间保持可见且一致。

## Risks

部分 Web 能力依赖浏览器专有原语或桌面本地资源，需要经过审慎设计的手机端表示，而不是直接视觉克隆。

如果网关重复验证或定义新状态，就可能偏离 DSH API；因此每条路由都必须委托既有 DSH 操作，并返回其持久结果。

手机端仍需要安全地初始连接到正在运行的桌面运行时；本次工作改变的是产品映射，不是本地安全模型。
