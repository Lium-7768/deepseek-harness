# Agent Note: 移动端一次性二维码配对

Status: implemented

[English](2026-08-19-mobile-one-time-qr-pairing.md) | 中文

## Problem

原生客户端此前要求用户从桌面控制窗口复制移动网关 URL、设备标识和访问令牌。该流程在手机上操作缓慢，会将长期凭据暴露给剪贴板和视觉复制错误，并且没有为新设备提供有时限的受控注册步骤。

## Decision

桌面控制窗口通过移动网关创建一个有效期五分钟、仅可使用一次的配对记录。网关仅保存高熵配对秘密的哈希，并将记录与不透明的配对 id 和可选设备标签关联。桌面将网关 URL、配对 id、配对秘密和过期时间编码为二维码。二维码载荷不包含长期设备凭据。

`POST /v1/pairing/redeem` 被刻意设计为唯一未认证的配对路由。它同时要求配对 id 和秘密，将过期或已消费记录以 `pairing-not-found` 拒绝，在返回前删除有效记录，并且只签发一次既有的长期已配对设备凭据。所有常规移动网关路由继续要求该设备凭据认证。

React Native 连接页将扫码作为主操作，同时保留网关、设备 ID 和令牌的手工输入作为恢复路径。`apps/mobile/app/connect/scan.tsx` 使用 `expo-camera` 的 `CameraView` 读取桌面二维码载荷，在本地校验其结构和过期时间，经 HTTPS 兑换，并通过 `expo-secure-store` 保存返回的凭据。无效、过期或已被兑换的二维码使用可恢复的 `pairing-invalid` 呈现，而不会泄露上游错误详情。

Expo 配置声明中文相机权限文本和 iOS `keychain-access-groups` entitlement。已检入的 iOS 工程和 Pod 锁文件登记 `ExpoCamera` 与条形码扫描框架，因此原生 iOS 构建包含扫码器。iOS 模拟器使用临时签名路径，最终 entitlement 字典可能显示为空；但生成工程中仍保留源 entitlement，供受配置文件签名的物理设备构建使用。

## Credential ownership and lifetime

配对记录是引导材料，而不是设备凭据。它在五分钟后过期，在签发凭据前即被消费，成功兑换或针对已过期记录的失败兑换后都不能再次使用。长期凭据仍是手机唯一保存的凭据，存放于操作系统安全存储，并继续适用既有的撤销与网关认证行为。

二维码刻意携带网关地址，因为首版跨网络传输仍是后续阶段。配对不会开放桌面 Web GUI 路由或原始桌面 API，不会引入独立移动账号，也不会改变桌面对会话和工作区数据的权威性。事件同步决策仍记录在 [Mobile Gateway SSE projection](2026-08-19-mobile-gateway-sse-projection.md) 中。

## Alternatives considered

**手工复制永久令牌。** 这复用了早期开发者流程，但会使日常注册容易出错，并让长期秘密进入手机剪贴板路径。它仅保留为受控环境下的恢复路径，不再是主交互。

**将长期凭据直接编码进二维码。** 这会缩短一次网络往返，但任何被捕获的二维码都会在显式撤销前持续有效。短时引导秘密限制二维码的暴露时间窗口，并让网关可以强制单次使用。

**要求已认证设备创建另一台设备。** 这可以避免未认证兑换端点，但会让第一次移动设备注册形成循环，并让桌面控制窗口依赖已有手机。桌面本地生成二维码才是受信任的注册动作。

**向扫码器公开桌面 Web 或 DSH API。** 这会绕过移动网关专用的凭据边界，并暴露不必要的桌面表面。狭窄的兑换端点将公开的配对词汇限制为引导数据和产生的设备凭据。

## Verification

网关集成测试验证一个生成的秘密只会产生一个长期凭据，并拒绝之后的兑换。移动 API 测试验证成功的未认证兑换请求，以及过期或已消费配对失败的本地呈现。移动应用、网关和桌面应用的严格 TypeScript 检查均通过，网关包也已成功构建。

iPhone 17 Pro、iOS 26.0 模拟器构建已链接 Expo Camera，并可在没有 SecureStore Keychain 异常的情况下打开连接页、二维码主入口和扫码路由。授予模拟相机权限后会渲染原生扫码容器和回退操作。模拟器没有可用的虚拟相机，因此其 AVFoundation 预览错误不能替代真机实际捕获二维码图像的验证。

## Consequences

用户可以在桌面控制窗口打开二维码并在原生客户端扫码，从而配对一台新手机，无需复制长期令牌。二维码载荷现在是一种版本化的引导格式，网关负责其过期和消费语义。这增加了一个狭窄的未认证端点和原生相机依赖，两者均被约束在注册过程中；它没有解决跨网络连接、真机相机验证、设备列表或撤销 UI、推送通知或云端身份。这些仍是独立的后续工作。
