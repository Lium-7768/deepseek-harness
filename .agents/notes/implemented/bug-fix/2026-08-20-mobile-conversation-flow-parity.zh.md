# Agent Note: 原生移动端对话流对齐

Status: implemented

[English](2026-08-20-mobile-conversation-flow-parity.md) | 中文

## Problem

原生会话页把桌面对话时间线压缩为用户气泡、助手 Markdown 和通用工具卡片。它丢失了助手推理块、模型重试披露、回合错误、真实工具名、关联工具结果以及回合级运行尾部。因此，桌面将 `Think`、`Tool call · bash`、重试失败详情和 `Deep diving...` 显示为独立行时，手机可能反复显示“工具 / 暂无输出摘要”卡片。

## Decision

`projectNativeConversationRows()` 直接从移动 Gateway 已返回的桌面持久会话事件派生有序原生显示行。它保留 `user/message`、助手 `reasoning` 与 `text` 块、关联的 `tool/call` 和 `tool/result` 生命周期记录、`llm/retry` 与 `turn/error`。该投影用关联结果更新工具调用行，并保留源序号以供附件和确定性的列表标识使用。

主原生会话以独立 React Native 组件渲染这些行类别。助手正文继续使用 `NativeMarkdown`；推理使用可展开的 `Think` 披露行；工具调用使用带状态点和可展开输入/输出的紧凑 `Tool call · <name>` 行；模型重试显示与桌面等价的延迟和失败原因；回合错误保持为提示；打开的持久回合在列表尾部独立显示 `Deep diving...`。列表键包含行类别和源位置，因为一个桌面助手事件可以同时生成推理行和正文行。

原生渲染器不复刻桌面 DOM、CSS、拖拽行为或检查面板。它将桌面持久信息及层级映射为满足触控尺寸的原生控件，同时保留系统文本选择、可访问性角色、安全区域布局和现有原生编辑器。

## Verification

移动端严格 TypeScript 程序通过。原生对话投影测试覆盖有序的用户正文、Think、助手文本、关联的失败工具输出、重试元数据、回合错误和活动回合时间。已配对的 iPhone 17 Pro 模拟器在运行中的桌面会话中显示真实的紧凑工具名、独立 Think 行、助手 Markdown 和工具状态点；列表键修复后未再出现重复 FlatList 键警告。

## Alternatives considered

**继续使用 `projectVisibleMessages()`。** 未采用，因为它的紧凑跨客户端投影刻意合并助手分块，并且只暴露用户、助手和工具记录。它适合简单转录视图，却无法表达主移动会话所需的桌面对话行差异。

**把每一个原始事件渲染为 JSON 或无差别通用卡片。** 未采用，因为事件完整性本身不能保留桌面阅读层级。持久事件需要一个小型移动专属投影来识别关联工具、推理、重试和回合错误。

**在 WebView 中嵌入桌面/Web 对话。** 未采用，因为产品决策要求移动客户端保持原生；原生披露、滚动、可访问性、附件分享和安全区域行为必须仍由 React Native 拥有。

## Consequences

手机对话现在以原生组件反映与桌面/Web 对话相同的持久信息类别和顺序。新增投影仅限主移动会话，并且只从桌面事件日志派生；它不创建移动 Agent Loop、不改变桌面事件 schema，也不开放桌面专属的工具检查和文件系统控制。未来新增桌面事件类别需要作出明确的原生行决策，不能静默落入助手 Markdown 或通用工具卡片。
