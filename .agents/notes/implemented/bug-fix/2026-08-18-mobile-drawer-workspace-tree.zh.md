# Agent Note: 移动端抽屉工作区树

Status: implemented

[English](2026-08-18-mobile-drawer-workspace-tree.md) | 中文

## Problem

原生抽屉只接收 `session.list`，因此无法复现桌面端的工作区成员关系和明确的未分组节点。品牌与控制项还直接放在抽屉滚动容器中，未为 iPhone 顶部安全区域留出空间。

## Decision

`MobileGateway` 与 `session.list` 一并请求 `workspace.list`，并在既有移动端会话列表响应中返回桌面端拥有的工作区标识、标题、路径、会话顺序和归档会话标识。React Native 抽屉过滤归档会话，按桌面端顺序渲染每个工作区，并始终为不属于任何工作区的会话渲染“未分组”。工作区节点始终保留在树中，仅展开或收起其子会话行，并向原生无障碍系统提供展开状态。抽屉使用覆盖顶部、左侧和底部边缘的 `SafeAreaView`；底部设置栏位于安全内容区域内，不再自行叠加安全区边距。会话已锁定时，智能体模式行保持禁用，但仍保留可读文字和明确选中对比度。

## Alternatives considered

**从会话标题或文件路径推断项目** 未被采用，因为这两者都不是桌面端工作区成员关系记录，并会创建与桌面端不一致的客户端分组规则。

**会话缺少工作区字段时继续使用移动端扁平列表** 未被采用，因为桌面工作区 API 已拥有成员关系和明确的未分组节点。

**只为品牌行添加顶部边距** 未被采用，因为搜索、视图控制项和未来的其他头部内容仍可进入 Dynamic Island 区域。

## Consequences

已配对桌面运行时必须为移动端会话列表请求提供 `workspace.list`。移动端用户会看到与桌面侧栏相同的项目成员顺序，以及明确的空或非空“未分组”行，并可在不移除文件夹节点的前提下收起任意项目。移动网关集成 fixture 和抽屉逻辑测试覆盖投影后的工作区成员关系、未分组回退与折叠子会话行为。
