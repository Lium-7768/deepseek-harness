# Agent Note：原生移动端交互与侧栏一致性

Status: implemented

[English](2026-08-16-native-mobile-sidebar-visual-parity.md) | 中文

## 问题

原生客户端把会话浏览器作为堆叠路由展示，改变了工作区上下文，也无法提供参考界面使用的左侧抽屉交互。同一批页面混用平台字形和文字 glyph，复制操作显示文字按钮，连接表单还贴在 Shell 边缘。待处理操作、设置和输入框控件也没有明确表达加载状态，或暗示移动网关尚未支持的修改。

## 决策

根 Expo Router `Drawer` 负责会话浏览器、左侧动画、可关闭遮罩、安全区和抽屉生命周期。`SessionDrawer` 只作为它的内容渲染器；旧的 `/sessions` 地址重定向到工作区，不再挂载第二个模态层。内容保留本地搜索、按数字时间戳的最近排序、其余会话展开、设置导航，以及明确禁用的“添加工作区（桌面端专属）”入口。只有会话摘要包含工作区数据时才启用按工作区分组；没有重排或创建操作时不声称支持手动重排或创建会话，因此抽屉显示禁用说明，并提供返回工作区入口。会话标题优先使用列表元数据，只有仍为占位符的行才有限读取 history。当前会话按路由中的 session id 高亮。`NativeIcon` 是本流程中原生客户端统一的语义 SVG 图标适配器。消息和代码复制操作只显示复制/勾选图标，短暂保留成功状态且不打断 transcript。`WorkspaceShell` 负责水平安全区内边距；每个表单或 composer 使用键盘避让容器，并保留已翻译的校验与操作文案。

`WorkspaceShell` 读取 `useSafeAreaInsets()`，将顶部安全区单独应用于自定义 header，而不是把它与内容混在一起；header 与 metadata 行使用共享的最小高度，并随文字增长。工作区、会话、待处理操作和连接页面根据顶部安全区与 shell header token 计算 iOS 键盘 offset，可滚动内容在拖动时收起键盘。根抽屉把官方 content props 传给 `DrawerContentScrollView`，由它提供抽屉安全区内边距和滚动。

待处理操作页面使用可滚动的原生列表，并明确展示加载、错误、未连接、空列表、下拉刷新和返回会话状态。审批与问题响应继续使用带版本的 Mobile Gateway 响应操作。Gateway 提供脱敏设置读取与安全默认值更新、提供方/模型目录、会话模型选择，以及 Agent 预设读取与选择；原生设置页和输入框使用这些操作，而不是发明本地修改。权限选项来自 host projection，并通过已有的 `/permission` 会话命令提交。附件、提供方凭据、插件编辑和自定义预设创建仍明确禁用或只读，因为移动端 contract 没有开放这些操作。模式与模型选择是桌面端持久决策，不是本地展示状态。

根抽屉导航会在打开会话、工作区或设置路由前关闭；已经位于设置页时点击设置只关闭抽屉。连接页和待处理操作页等不需要会话导航的页面隐藏菜单，并在需要时使用明确的返回操作。品牌区域使用既有 whale 标志，`NativeIcon` 使用 `react-native-svg` 绘制统一的 24px outline 图标集合，不依赖平台字体 glyph 度量。紧凑图标操作的命中区至少为 36px。连接失败保留在已翻译的内联错误区域中，不直接暴露原始请求文本。

原生页面在 390px 参考宽度上使用 Web 会话几何：设置页只保留一个 16/24 标题并使用 24px 内容内边距，抽屉使用 60px 品牌行和 38px 新会话行，Tab 使用内容宽度并保持 36px 间距，消息气泡使用 Web 的 22px 圆角与 16/24 文字度量，输入框使用 34px 圆形发送控件和无边框 28px 工具控件。统计行使用透明背景的 12/20 文字。Expo 开发菜单浮层不属于产品布局验收范围。

## 考虑过的替代方案

**保留作为路由推入的会话页面。** 不予采纳，因为路由会替换工作区上下文，并产生第二个导航所有者，而不是使用根抽屉的遮罩和从左侧关闭的交互。

**在已有图标组件旁继续使用字符 glyph。** 不予采纳，因为 glyph 的度量和含义会随字体与平台变化，工具行无法与原生客户端的其余部分匹配。

**每次复制后显示成功提示框。** 不予采纳，因为提示框会打断阅读，而勾选图标已经提供视觉确认。

**保留静态待处理操作列和提示框。** 不予采纳，因为较长的操作列表无法可靠阅读，提示框还会暗示移动端支持未实现的附件、权限或模型修改。

**新增只供 UI 使用的附件或设置 API。** 不予采纳，因为支持的设置使用现有 host settings seam，而附件仍没有允许移动端使用的操作或持久语义；在 UI 中发明这些行为会使移动端偏离桌面运行时。

**把返回工作区的路由标为“新会话”。** 不予采纳，因为 Mobile Gateway 没有创建会话操作；该控件会暗示创建了新的持久会话，实际发送时却会使用已有会话。

## 后果

根左侧抽屉打开时工作区仍显示在后方，选择会话或设置入口会先关闭抽屉再导航。搜索与最近排序保存在抽屉本地，列表每次刷新只请求一次；只有列表元数据仍是 fallback 标题的行才读取 history。首版 Mobile Gateway API 提供带数字时间戳的会话列表，但不提供工作区分组、重排、创建、工作区变更或目录选择操作；同时提供脱敏设置与模型/预设操作，让受支持的默认值和会话选择可以实际生效。抽屉会禁用不支持的分组/重排选项，使用返回工作区而不是假称创建会话，并明确说明添加工作区需要桌面应用。原生 shell 保留 whale 品牌锚点，session/workspace 上下文行的最小高度分别为 48px 与 35px；文字放大时行可以增长，不会裁切。Shell 使用 35px tabs 与 2px active 指示线，composer 使用 22px 圆角，并将桌面端专属能力显示为禁用的次级控件。

`app.json` 继续同时声明 `orientation: "portrait"` 与 `ios.supportsTablet: true`。Expo 文档说明 portrait orientation 是显式锁定；本次没有明确的产品要求允许改变它，因此不根据 tablet 标志推断 iPad 横屏或分屏策略，相关策略继续延后。

待处理操作在小屏幕上仍可使用，失败时有可见的恢复路径。用户可以区分手机支持的操作和仅由桌面端控制的状态。附件、提供方凭据、插件编辑和自定义预设创建仍不可用；UI 会明确说明这些限制，而不是静默丢弃点击。受支持的设置默认值以及会话模型或 Agent 预设选择通过 Gateway 操作提交，由桌面端验证并保留持久语义。

## 验证

实现遵循官方 [Expo Router drawer 指南](https://docs.expo.dev/router/advanced/drawer/)、[React Navigation 安全区指南](https://reactnavigation.org/docs/handling-safe-area/)、[React Native KeyboardAvoidingView 指南](https://reactnative.dev/docs/keyboardavoidingview) 与 [Expo 屏幕方向参考](https://docs.expo.dev/versions/latest/sdk/screen-orientation/)。移动端 TypeScript 与 focused Vitest 测试固定共享 shell 几何和抽屉行为；具体结果随实现报告。此前的原生 iOS 截图覆盖连接表单、工作区覆盖层和会话抽屉，但最终 Metro 启动被导入 `node:crypto` 的旧生成桌面端 `index.mjs` bundle 阻塞，因此这些截图不能证明最新抽屉源码。
